## Свежесть обычного запуска и отдельная идентичность M10

Обычные `eng/run-act1-demo.sh` и `eng/run-act1-demo-safe.sh` раньше сразу
запускали лежащую в `game/.godot` DLL и compiled pack, даже после изменения
их источников. Теперь общий wrapper сначала вызывает существующий
`eng/compile-game-content.sh`, затем incremental build `game/Urman.Game.csproj`.
При ошибке контента или C# игра не запускается; безопасный wrapper делегирует
обычному, сохраняя Mobile, safe mode и все дополнительные аргументы.

M10 запускает отдельный экспорт, поэтому новые исходники не означают, что
выбранный app уже обновлён. `eng/run-m10-playtest-session.sh --resolve-only`
теперь читает фактический PCK и DLL, сравнивает Chapter I/full-game pack с
checkout и связывает распакованные binary/PCK/DLL с macOS ZIP и его receipt.
Исходный `read_pck` из `verify-act1-release-package.sh` вынесен без изменения
проверок в общий `eng/godot_pck.py`; проверка идентичности не запускает Godot.
Оба существующих desktop exporter сначала выполняют content compile/import
preflight, затем снимают SHA всех контентных источников, game source/asset/import
settings и .NET source/config перед настоящим export. После успешных macOS и
Windows export и упаковки повторный снимок обязан совпасть. Только тогда
`eng/desktop_build_provenance.py` записывает fresh provenance с run UUID,
точными mode/presets и SHA/размером всех трёх полученных артефактов.
`verify-desktop-artifacts.sh` заново проверяет canonical SHA обеих карт файлов
и их связь с проверенными артефактами, включая перенос staging → final.

Самостоятельный structural verifier сохраняет лишь `source.verificationSnapshot`
и `buildProvenance.status=unverified`. Старое `source.inputManifest` не принимается
как доказательство сборки: старый ZIP + правка C# + повторный verifier не становятся
актуальным кандидатом. M10 требует completed exporter provenance, совпадение
нынешних исходников и реального набора артефактов. Dirty checkout распознаётся
по содержимому, а не по одному HEAD/списку путей. Before/after snapshots требуют
согласованной остановки правок на время сборки; краткую правку с откатом между
снимками они не обнаруживают и независимой аттестацией компилятора не являются.

Имя каталога используется только для выбора кандидата. По умолчанию поиск
идёт в `build/native_*_candidate`; `URMAN_M10_CANDIDATE` и
`URMAN_M10_EVIDENCE_ROOT` сохраняют возможность выбрать конкретный иной путь.
Каталог результатов допустим в `build/` либо вне исходных папок. Каждый
начатый сеанс получает `candidate_identity_*.json` рядом с хронометражем и
ссылку на него в бланке наблюдателя. Несовпадающий либо неподтверждённый
кандидат можно осознанно измерять командой
`sh eng/run-m10-playtest-session.sh --historical <каталог-результатов>`;
режим фиксируется в JSON и бланке. Различие Debug/ExportRelease DLL само по
себе не означает устаревшую сборку: это разные артефакты компиляции.

Обычный M10 теперь вызывает существующий `protected_run.py --clean`: у сеанса
нет прежних слотов, настроек и `debug-zones.enabled`, пользовательское userdata
после завершения восстанавливается. Каждый полный экран сохраняется с порядковым
номером и UTC временем через exclusive link; кадры одного дня или одной секунды
не перезаписывают друг друга. Source14 timing collector сохранён побайтно.

Документированный r45 относится к git `483813aae0f71081d876495946eb28927cdb62fc`.
Его исторический git pack имеет fingerprint
`6eb1d1e2f6d7e293e20953e849110f92680b5c249a311537ba3f400ccb218a9a` и ещё
автоматически выдаёт понимание дома/пяти evidence-сцен при входе. В нём нет
восстановленных личных источников приезда, возвращения к Наиле и Алсу с
вопросами, вопросов по черновику/учёту и наблюдения Рината. Это сравнение
**git-контента указанной ревизии** с текущим контентом, не чтение внешнего app:
прямой доступ к старому кандидату вне approved roots был отклонён. Факт
пользовательского запуска r45 и пятиминутный замер этим не установлены.

Проверены POSIX/Python syntax и изолированные fixtures: отказ сборки не
запускает engine; safe flags/аргумент с пробелами сохранены; изменение файла
с прежним mtime, удаление исходника, иной pack и подмена распакованной DLL
обнаруживаются; старый receipt остаётся unknown и требует явного historical
режима; разные before/after manifests и неверная связь с артефактами отвергаются.
Контрпример «старый export → правка C# → standalone verification» проверен и
остаётся unknown. Независимый source review новых exporter/receipt/identity
контрактов не нашёл блокера. Полный M10 mock завершился exit 0: девять разных
кадров, настоящий guard с пустым временным userdata и точным восстановлением
исходных save/debug sentinel, parser с terminal event и открытой человеческой
приёмкой. Настоящие игра, снимок экрана и пользовательские файлы в mock не участвовали.
Тело существующего PCK reader и source14 timing parser сохранены.
Реальные engine/build/export вызовы в этих проверках **not-run**; новый
экспорт проверяет root после сериализованной сборки. Эти проверки не являются
первым человеческим прохождением или подтверждением 60 активных минут.

## B16: фактический вид дороги перед выводом по схеме

Подтверждённый содержательный пробел исправлен в существующем владельце:
чтение бирки больше не описывает взаимное расположение канавы и ограды одним
нажатием. `compare-route-match` теперь требует уже существующий
`clue_sketch_field_landmarks`; итоговое знание ссылается на схему, бирку и
отдельное полевое наблюдение. Нижнее крепление бирки, снег и дополнительное
`clue_sketch_place_compared` остаются необязательными.

Общий `Act1RouteLandmarksProof.ObserveAsync` использует reference metadata
действующего target, обычную стоящую капсулу на настоящей опоре, реальный ray
FPC и target.Interact. Поворот от ориентиров должен отказать без выдачи знаний.
Chapter проверяет порядок «бирка → ошибочная версия → save/load → перепроверка
→ фактический вид → сопоставление»; LEN — «вид → save/load → перепроверка →
бирка → две исправимые версии → сопоставление». До обоих источников прямой
положительный dispatch и финальный проход запрещены. Final использует тот же
helper. Тесты не выставляют knowledge или scene flags вручную.

Content regression фиксирует эти условия и необязательность нижней детали.

## B17: выписка из открытого источника вместо готового ответа

В существующих документах игрок включает выделение, выбирает целую исходную
строку или предложение и сохраняет выписку. Четыре локальных действия
`excerpt-notice-cause`, `excerpt-register-wording`, `excerpt-register-category`
и `excerpt-message-voice` записывают соответственно
`clue_notice_cause_excerpt`, `clue_register_wording_excerpt`,
`clue_register_category_excerpt` и `clue_message_voice_excerpt`.
Тексты взяты из самих доступных документов; UI не предлагает правильные цитаты
отдельными кнопками. Прямой dispatch действия, точный текст без текущего
выделения, скрытый reader и прежняя session не дают выписку. Runtime сохраняет
активную сцену и использует существующий checkpoint. Источник принадлежит
действию через точную reader binding, без перемещения в служебную сцену.

Сопоставление бумаг требует двух выписанных полей. После показа Наиле этих строк
игрок показывает выбранную категорию и получает прежний ограниченный ответ.
Неправильная медицинская трактовка сохраняет прочитанную выписку, но устанавливает
`npc.naila.category_excerpt_review_requested=true`. Готовой правильной кнопки
исправления нет. Обычное повторное открытие документа не снимает ошибку; нужно
заново выбрать исходную строку. Только повторная запись снимает request, после
чего доступно «Показать уточнённую выписку» и прежний человеческий ответ.
Необоснованная гипотеза исправляется этим ответом, а не самим выбором текста.

У сообщения удалено прежнее `compare-message-heard`: точную выписку теперь
готовит `excerpt-message-voice`. Оно сохраняет совместимый факт
`clue_message_question_prepared`, но страх, ответ Алсу и следующий источник
по-прежнему требуют настоящего возвращения и разговора. Ошибочная версия
о встреченном человеке остаётся исправимой; скрытые канонические факты не добавлены.

Общий `Act1SourceExcerptProof` открывает существующий журнал, выбирает настоящий
диапазон `TextEdit`, нажимает реальные Begin/Record/Back и проверяет ошибочный
заголовок, отмену, direct dispatch, единственную запись и отсутствие scene transition.
LEN дополнительно сохраняется между двумя выписками и после повторного выбора
категории. Chapter, LEN, OldPc и остальные владельцы flow tests используют один
helper. `SourceExcerptUiProof` исследует клавиши и границы окна 720/1080 в native
режиме; headless явно помечает эту часть external/not-run и продолжает проверки
записи источника без выдуманного window/render результата.

[integrated-build-17.json](../../../docs/production/act1_takeover_evidence_2026-09-16/integrated-build-17.json)
подтверждает content compile, C# build и import exit 0, неизменные входы:
DLL `cfeb7fdfb66c022be93ec9f0fba141623f82c6e96a544e0cff9ed6e3056700a6`,
Chapter pack `5e5b617f7f7e28d56e9b57240d84405cc619edda588131f539a8321e40cdd373`.
Source review и 7/7 content checks пройдены.
[len01-10](../../../docs/production/act1_takeover_evidence_2026-09-16/len01-10.json)
и его [лог](../../../docs/production/act1_takeover_evidence_2026-09-16/len01-10.log)

## Карта обязательного опыта — текущие B17 sources; прежняя полная проверка B12 ниже

разговоры допускают разный порядок. Сокращён префикс `urman.chapter1:`;
архивные документы принадлежат `urman.oldpc:`. Завершённое прохождение
всего пути ногами ещё не доказано; границы проверки приведены после карты.

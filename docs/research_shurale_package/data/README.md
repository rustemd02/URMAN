# Реестры и типы данных

Кодировка CSV — UTF-8 с BOM; разделитель — запятая; стандартное CSV-экранирование. Массивы ID внутри CSV сохранены как JSON-массивы, чтобы не потерять тип. Поле source_urls дает прямые адреса источников. JSONL — UTF-8 без BOM, один объект на строку, поле record_type определяет реестр. Полный эквивалент — database.json.

Пустая CSV-ячейка соответствует null / неустановленному значению, а не нулю и не доказанному отсутствию. В JSON null сохранен явно. Массив [] означает отсутствие прикрепленной ссылки в данном пакете, а не отсутствие свидетельств вообще.

S — источники; C — утверждения; V — визуальные референсы; AV — звук/видеокандидаты; D — размеры; A — объекты; P — растения; SE — сезоны; T — хронология; TT — термины; L — поселения; H — хозяйства; MF — мотивы; SC — сцены; G — пробелы; LT — расчетный свет.

## Важнейшие различия

observed_value и proposed_game_value никогда не объединяются. Для проекта численное значение задано, а не измерено. Геометрический расчет света имеет статус «Оценено» и открытый метод. Звуковое actually_listened=false не разрешено автоматически менять на true. Путь local_path существует только у реально сохраненных файлов. Музейное classification нельзя преобразовывать в «современный жилой дом».

assets содержит производственные карточки: его источник может подтверждать отдельную форму, но не всю игровую комбинацию материалов/размеров/размещения. Перечень растений разделяет региональное присутствие, локальное наблюдение и игровую высоту. Хронология различает старт технологии/канала и присутствие в конкретной семье.

research_database.xlsx содержит те же реестры с читаемыми заголовками, таблицами, фильтрами и закреплением первой строки. Обзор показывает количество записей формулами, не число прочитанных книг или обследованных хозяйств.

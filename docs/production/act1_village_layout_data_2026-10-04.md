# Данные планировки деревни: состав и «retired» — 2026-10-04

Аудит авторского файла планировки `game/content/world/act1_village_kit.world.v1.json`
(196 постановок компонентов китов). Игра не запускалась; выводы — только то, что видно в
данных, без догадок о замысле.

## Состав файла

- Всего **196 постановок**, из них **96 активных** и **100 помечены `retired: true`**
  (51 %). Это состояние миграции: в `note` файла сказано, что постановки компонентов,
  которые раньше задавал код сборки деревни, теперь живут здесь.
- Активная часть — в основном дорожная и рельефная обвязка: `RoadRuts` 8,
  `RoadsideDitch` 7, `VillageParcel` 7, `MuddyShoulder` 6, `RoadCrown` 4, `ForestBank` 4,
  `MixedTreeCluster` 4, `RootWall` 4, `GrassSedgeMass` 3, `OutbuildingShed` 3.
- Активных постановок **жилых домов — 5** (вариант A 1, B 2, C 1 и один
  `DwellingFacade_TimberPlaster`). Остальные жилые постановки (всего их в файле 44) —
  retired; поэтому число вариантов семейства домов по этому файлу судить нельзя:
  живая застройка частично строится кодом (`Act1ConnectedWorld.*`).
- Привязки (`params.logicalAnchor`) распределены по местам: `village_day` 89,
  `zirat_road` 30, `village-house` 20, `kara_urman_night` 19, `fap_clinic` 15,
  `house_old_pc` 14, `house_to_zirat` 9.

## Находка: у 90 из 100 снятых постановок не записана причина

Из 100 retired-постановок **только 10 несут `note` с причиной**, например:
`«29.09: authored overlap remediation; H001 inside ArrivalFarWestFacade; next plot north»`
и `«H005 inside ArrivalReverseEdgeHouseEast; next plot east…»`. Остальные **90 снятых
постановок не объясняют, почему сняты**. По составу снятых: `FenceSegment` 25,
`VillageParcel` 24, `OutbuildingShed` 21, `DwellingFacade` 18, `Woodpile` 7, `Gate` 4,
`RoadCrown` 1.

Это не обязательно ошибка планировки — но это пробел прослеживаемости: по файлу нельзя
отличить «снято осознанно при переносе участка» от «снято случайно/осталось от прежней
раскладки». Правильный следующий шаг — не переписывать данные, а дописать причину к
снятым постановкам (она восстанавливается по истории git и по заметкам ремедиации
29.09), как это уже сделано для десяти. Формулировка «причина обязательна» не выдумана:
файл сам начал так делать 29.09.

Дополнительно проверено: снятые компоненты (`Gate_CrookedTimber`,
`OutbuildingShed_Low`, `DwellingFacade_TimberPlaster`, `VillageParcel_VariantA_TimberGable`,
`FenceSegment_RoughPicket`, `RoadCrown_BranchWet` и другие) **остаются упомянутыми в
коде** (1–3 скрипта на компонент). Это ожидаемо, пока код умеет искать и снимать такие
постановки, но при будущей чистке нужно помнить, что «retired в данных» ≠ «не
упоминается в коде».

## Что это значит для карточек

- `ACT1-VILLAGE-LAYOUT`: нужен один проход «причина для снятых постановок»; сами данные
  переписывать не требуется.
- `ACT1-DEPTH.10`: число и распределение вариантов жилых домов по этому файлу **не
  выводится** (5 активных) — семейство оценивается по коду сборки и кадрам, а не по
  числу активных постановок.
- `ACT1-PUBLIC.FACADES` (R072): в этом файле общественные здания не описаны
  (`school`/`council`/`club`/`shop` не встречаются), их форму задаёт код
  (`BuildClosedSchool`, `BuildCouncilClub`, `BuildVillageShop`), а ФАП приходит из своего
  кита (измерено: `Fap_Body` 9.02 × 2.54 × 9.48 м — заметно крупнее жилых). Значит
  «отличимость архитектурой» подтверждается разными сборщиками и китом ФАПа, а внешний
  вид — кадром, который остаётся `not-run`.

Границы: это аудит данных и их прослеживаемости, а не художественная оценка застройки.

## 2. Исправлено в этом прогоне

1. **«Взять входящее» на конфликте порядка уничтожал документ.** `SemanticMerge`
   кладёт в конфликт порядка последовательность ID, а `ConflictResolution.Set`
   записывал её по месту списка: на корневом списке модуля (файл модуля — это
   массив сущностей с путём `""`) весь документ превращался в массив строк-ID.
   Теперь решение по порядку выполняет `ConflictResolution.Reorder`: сущности
   переставляются, объекты сохраняются, не упомянутые в порядке остаются на своих
   местах. Покрыто двумя тестами (корневой список и `/stages` внутри квеста);
   до правки оба падали.
2. **Восстановление черновика падало на осиротевшем манифесте.** `DraftStore.Recover`
   читал `*.meta.json` без своего `.draft` и бросал исключение; теперь такой
   манифест пропускается.
3. **Ревизия в контексте разработчику могла быть мусором** (`refs/he`) в checkout с
   упакованными ссылками: `DeveloperContext.Revision` читал только
   `.git/refs/...`; добавлено чтение `.git/packed-refs`.
4. **Разбор конфликта порядка показывался автору сырым** (`["a","c","b"]`) и с
   пустым именем для корневого списка. Теперь порядок показан именами через
   «→», а корневой список назван «весь файл».
5. Устаревший текст заглушки разделов («сейчас работают только „Мир“ и „Квесты“»)
   заменён на фактический список работающих разделов.

атомарным списанием и выдачей, «требуется новая механика» для отсутствующих
действий, правила для предмета, полученного до квеста или потраченного.

## 4. Открытый технический долг

1. Разрешение «удаление против правки» возвращает сущность в конец списка, а не
   на прежнее место: для этапов квеста это меняет порядок исполнения.
2. `QuestFlow` повторяет правила неявного «следующего этапа» из
   `QuestLifecycleReducer` собственным кодом — связь только тестами и
   комментарием; расхождение возможно молча.
3. Данные мира и сцены вне компилятора и без схем (см. P2).
4. Нет обратной проверки, что каждая постановка генератора покрыта файлом
   участка (`Unmatched()` ловит только лишние якоря).
5. `ReferenceIndex`/`EntityCatalog` пересканируют рабочее пространство на каждый
   запрос — упор в цель §21 по поиску.
6. Масштаб интерфейса не выведен в окно (`UX06`: 100–150 %), тема умеет
   масштаб, значение зашито 1,0.
7. `StudioCutscenePanel` и шаблон квеста привязаны к одной сцене/одному шаблону.
8. Отслеживание внешних правок опрашивает диск раз в 2 с; при быстрой чужой
   записи возможна потеря между проверками.

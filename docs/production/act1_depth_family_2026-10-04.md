# Объём вместо плоских заглушек: инвентаризация — 2026-10-04 (ACT1-DEPTH.1–.12)

Проверено по данным и коду; игра не запускалась. Художественная приёмка (кадры) — `not-run`.

## DEPTH.1 — инвентаризация плоских заглушек (главный результат)

Проверено две независимые совокупности.

**1. Каталог мира `game/content/world/catalog.v1.json` — 177 объектов.** У каждой записи
есть `size` (габарит), `category`, `collision`, `kit` и `license`. По `size` **ни один объект
не является плоским**: минимальная ось у всех ≥ 6 см, то есть в каталоге нет ни одной
плоскости, выдающей себя за объём. Это снимает половину вопроса по DEPTH.1 и DEPTH.8
доказательно, а не на слово.

**2. Код сборки мира (`Act1ConnectedWorld*.cs`, `StyleBenchmark*.cs`).** Найдено **150**
вызовов геометрии с одной осью тоньше 2.5 см. Разбор по именам показывает, что это
**поверхностные детали, а не имитации объёма**: `MosqueEntranceMat` (коврик),
`MosqueEntranceCourtesyPaper` (лист), `MosqueHeatingVent` (решётка), `HingeStrap` (петля),
`WhiteSignField`/`BusSilhouette`/`BusWindow` (поля знака остановки), `WallCalendarPage`
(страница календаря), `MatchboxSleeve` (коробок), `RadioGrille` (решётка радио),
`HallRunner` (дорожка), `LogEnd` (торец бревна). Плоскость здесь — правильная форма детали,
а не заглушка мебели или постройки.

Остаток для владельца: **18** таких вызовов не имеют рядом строкового имени, поэтому их
назначение определяется по месту (`file:line` есть в отчёте). Ни один из них не объявлен
дефектом без просмотра.

## Границы

Инвентаризация проверяет **форму** объектов по данным и коду: есть ли плоская имитация
объёма. Она не оценивает, красиво ли сделан объём, и не заменяет кадры; «нет плоских
имитаций» подтверждается числами, «объём выразителен» — только просмотром.

## Библиотека вариантов — R077

Вариант выбирается детерминированно: `variant = StableHash(lot.Id) % 5`, то есть **ровно
пять** вариантов на участок (`Act1ConnectedWorld.YardFences.cs:177`), и параметры у них
различаются осознанно, а не случайно:

| Параметр | Значение |
|---|---|
| Высота уличной ограды | `1.10 + variant·0.045`; дворовой — 1.38 |
| Шаг штакетника | `variant 3 → 0.30`, `variant 4 → 0.22`, иначе 0.17 |
| Ширина штакетника | `variant 3 → 0.055`, иначе 0.095 |
| Форма верха | `variant switch` (свой профиль у каждого варианта) |
| Доп. наборы | варианты 0/2/3/4 добавляют свои ряды |
| Материал | улица — `wood_painted_trim`, двор — `wood_fence` |

Это уже «согласованная библиотека около пяти вариантов», а не несвязанное разнообразие:
различие задано таблицей параметров, а не произволом на месте. Кит даёт части
(`FenceSegment_EndPost_00/01/02`, `FoundationStoneLeft/Right`, `Picket_00…06`,
`RoughPicket`, `RailLower/RailMiddle_Crooked/RailUpper`), код собирает из них пролёты.

## Посадка и «парящие» заборы — R066, Z11/I11

Правило уже действует и совпадает с общим правилом посадки из
[act1_placement_rules_2026-10-04.md](act1_placement_rules_2026-10-04.md), пункт 3:
высота берётся из рельефа, а не из догадки. Каждая стойка пролёта ставится по
`AgentBAct1HeightField.CollisionGround(p.X, p.Y)`, а рейки соединяют соседние точки
грунта (`:250`, `:258-259`) — то есть пролёт повторяет рельеф и не висит. Значит для класса
Z11/I11 правило **есть**; остаётся применить/проверить его на конкретных экземплярах
(это уже работа по месту, а не отсутствующая система).

Дополнительно требуется уточнение владельца: в ТЗ 03 строка `I11` помечена как «висящий
забор», причём сам источник допускает латинское `I` **или** кириллическую `И`
(`03_world_geometry.md:66`). Пока не решено, о каком именно объекте речь, менять нечего —
иначе легко «исправить» не тот забор.

## Стыки и пересечения — R029

Стык обрабатывается правилом обхода граней: «сначала передние грани, чтобы общий угол
сохранял уличную лицевую сторону» (`:95`), и «любая грань, смотрящая на улицу (боковая
сторона углового участка), получает уличный штакетник» (`:193`); углы и составные рейки
поддержаны частями `RailMiddle_Crooked`. Пересечение двух оград разных владельцев (К15/Л15)
— это конфликт **размещения/владения**, а не отсутствие правила стыка: чтобы его снять,
нужно решение по границе участков, а не новая система.

## Сохранение положительного образца — R028

Унификация не удаляет конкретные ограды: пролёты строятся из данных участков, а вариант —
из хеша их id. Поэтому И15/И14 сохраняются по построению, если не менять данные участка.
Что нужно от владельца: подтвердить, какие именно участки соответствуют И15/И14 в исходных
кадрах (19) — в коде и данных плановых литер И/К/Л/Z нет, они пришли из разбора автора.

Три требования из четырёх (R066, R077 и стыковая часть R029) уже опираются на действующие

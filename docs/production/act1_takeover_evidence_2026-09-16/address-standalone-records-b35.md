# Четыре самостоятельных источника: интеграция B35

Это продолжение четырёх ошибок владельцев Address08, а не новая очередь. Мир и предложение 16 домов не перемещаются. B34 native inputs сохраняются; изменены только согласованные C# sources/tests для следующей интеграции.

`SettlementBuilding.AddressId` и аргумент address у `SettlementRegistry.Register` уже nullable. Три сарая используют эту существующую модель: собственные building/parcel/access, без жилого номера, адресной таблички, знания, NPC или выдуманной семейной принадлежности. Фактический вход берётся из `OutbuildingShed_Door_Panel_LOD0`, approach — по его наружной нормали; до физической проверки state остаётся `pending-physics`. Общий `AddressAccessVerifier` и тот же граф проверяют реальную опору, стоячее тело и маршрут. Наличие записи не объявляет доступ проверенным.

| ZiratVillageEdgeEastShed / `act1/outbuilding/ZiratVillageEdgeEastShed` | `BLD-3BE818BAD103E824` / `PAR-3BE818BAD103E824` / `ACC-3BE818BAD103E824` | `URM-Q01-P0201` |

Источник каждого сарая сверяется с точным существующим `logicalAnchor`, не с ближайшим соседом или количеством детей общей presentation-группы. Кадастровые записи вымышленные и уникальны относительно текущего manifest/source. Register сохраняет общую проверку уникальности и ссылок. Validate теперь проходит реальные зарегистрированные parcels, поэтому несколько сараев на общем участке не создают повторных требований; независимый безадресный участок больше не выпадает из проверки доступа. Notebook по-прежнему проецирует только действительно известные адреса.

`ReturnWestBanyaSilhouette` — отдельный существующий жилой VariantA. Его production binding ещё **не применён**. Подготовленный [candidate patch](address-returnwest-candidate-b35.patch) сохраняет геометрию и явно выбирает настоящий SeniEntry, но применяется только после проверки его опоры/доступа/луча/полного крепления и номера. SourceKey `act1/holding/ReturnWestBanyaSilhouette` даёт стабильные `BLD-478E6ADBD3A5D7CF`, `PAR-478E6ADBD3A5D7CF`, `ADR-478E6ADBD3A5D7CF`; обычный importer создаст `ACC-ADR-478E6ADBD3A5D7CF`.

Число25А уже закреплено за скрытым `ReturnWestFarmVolume` (manifest ADR-H058), поэтому оно не свободно. Перед импортом видимых зданий `BuildAddressRegistry` теперь резервирует весь manifest через существующий Registry `_search`; отдельного номерного владельца нет. Retired reservation не создаёт адресной записи/места в книжке. `InfillNumber` использует тот же индекс и сохранённые history aliases. Кандидат25Б остаётся кандидатом до native: proof измеряет реальный вход на ближайшей существующей улице, расстояние по её общему графу от фиксированного начала, сторону и ближайшие существующие номера той же чётности. Никакие прежние номера не меняются.

Узкий запуск для root после B35 build: существующая сцена `res://tests/address_world_smoke_test.tscn`, `URMAN_ADDRESS_SCOPE=standalone-candidates`, новый пустой абсолютный `URMAN_ADDRESS_OUTPUT`, обычные guarded native условия. Он сохраняет четыре actual-source записи в `address-standalone-candidates.json`; общий долгий audit приостановлен только в test scope и восстанавливается в finally. Все прямые пути имеют предел1000 продвижений по≤8см. Отказ прямого пути не означает, что все обходы закрыты. Дверные детали сарая (panel/planks/handle одного подтверждённого узла) записываются как точные допустимые владельцы луча. Табличка сараям не требуется; для жилого ReturnWest проверяется весь настоящий mount. Актёр, состояние, реестр и source transforms остаются неизменны; `acceptance=false`.

Pure regression — существующая `res://tests/address_registry_smoke_test.tscn` headless через guard после B35 build. Проверяет собственный nullAddress parcel, repeat import без выдуманного жилого адреса, включение доступа в Validate, отсутствие утечки в notebook, невозможность неполной адресной ссылки, retired25А→25Б и повторный enriched import без перенумерации. На момент подготовки этой записи новые проверки ещё не запускались; .NET/Godot/import выполняет root последовательно.

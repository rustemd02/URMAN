Задача: `docs/tasktracker/TASKS.md` ACT1-OLDPC-SHELL; ТЗ `docs/tasktracker/03_oldpc_full_system.md`
§9.4 (снапшот, схема и провайдер меняются вместе: `Applications += chat, tetris`, окон ≤ 9,
`chat/hintsSeen/tetrisHigh`, миграция старых сейвов, доступность новых окон).
Основание: слияние синхронизации `21d041e`; правки этой задачи — поверх него.

## Что сделано

- `src-dotnet/Urman.Core/Capabilities/OldPc/OldPcDesktopSnapshot.cs`
  - `Applications`: 7 → 9 (`chat`, `tetris`); предел окон следует за списком программ.
  - Новое состояние: `chat` (тредов ≤ 4 из `alsu/rinat/mansur/self`, сообщений ≤ 64 на тред,
    текст ≤ 500 знаков, `from` = `npc|player`, `unread`), `hintsSeen` (≤ 64 уникальных id
    по ≤ 64 знака), `tetrisHigh` (0…999999). Новые поля — не `[JsonRequired]`, поэтому сейв,
    записанный до них, читается со значениями по умолчанию.
  - Миграция: неизвестный id окна отбрасывается вместе со ссылкой активного окна; форма
    повреждённого окна по-прежнему отвергается. Load не падает (проверено тестами).
- `content/modules/urman-oldpc/schemas/oldpc-state.schema.json` — зеркало: `maxItems` 9,
  enum `+ chat, tetris`, свойства `chat/hintsSeen/tetrisHigh` с теми же границами.
- Провайдер отдельно не менялся намеренно: десктоп-состояние проходит через тот же класс
  снапшота (`OldPcDesktopSnapshot.Restore`), поэтому C#, схема и провайдер остаются одним
  владельцем границ.
- Игровой UI: `OldPcUi` сериализует и восстанавливает `OldPcDesktopSnapshot` целиком,
  поэтому новые поля переживают save/load без правок UI; `RestoreDesktop` уже пропускает
  неизвестные UI окна. Применение доступности идёт по всему дереву `_screen`
  (`ApplyDesktopAccessibility`), поэтому будущие окна чата и тетриса попадают под него без
  отдельной регистрации.
- Никакого знания новые поля не несут: снапшот остаётся презентационным, `accessConditions`
  остаются единственным владельцем знаний.

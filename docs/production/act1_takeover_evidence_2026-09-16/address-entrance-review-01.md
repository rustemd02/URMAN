Подготовлен [единственный data patch H016](address-primary-h016-b34.patch): добавить `primaryDoor: DwellingFacade_SeniEntry_Door0_Leaf_LOD0`. Он не перемещает/удаляет ни одну дверь, сохраняет `BLD-H016`, `PAR-H016`, `ADR-H016`, `ACC-ADR-H016`, sourceKey, кадастровый ID, номер15 и историю. Адресный импорт сам заново получает access/sign/knock из настоящей выбранной двери; числовые мировые координаты в данные не копируются. В момент подготовки patch runtime JSON оставался frozen SHA `ad8a960784c6f9987578dfcbcee8ba3b686b0052254b952e3c7931b367e60920`; patch не выдаётся за уже применённый. После применения нужны actual import/graph attachment и ручное действие на новом владельце.

H009 не переключён. Основной Front_BoardedGable начинается на Y≈2.704: центр полной таблички должен быть не ниже2.944, что здесь выше установленного ограничения facadeGround+3м. Вместо слепого повышения высоты B34 проверяет **существующую наружную SeniOuter и основную Right_Wall**, обращённые к дороге; их происхождение — `author_rural_dwelling`, строки2092 и2203 текущего генератора. Exact-owner overload не меняет default policy, размеры таблички, ограничения высоты, polygon coverage или препятствия перед фасадом. Все прямые проходы и реальные опоры остаются обязательными.

B34 narrow scope дополнен диагностическими кадрами с физически поддержанной точки дороги и точки подхода, обычными FOV и высотой глаз. Если место поддержано, временная `AddressSignVisualComponent` показывает точные строки реестра и номер без InteractionTarget/коллизий/записи знания, находится вне игрового world и удаляется в finally. Это preview возможного крепления; никакого принятого производственного адреса или человеческого поиска он не изображает. При отсутствии опоры кадр с висящей камерой не подставляется. Нативный результат B34 на момент записи не выполнен.

Уточнение перед сборкой B34: после закрытия всех B33 native запусков root применил подготовленный patch H016. Повторное чтение live manifest подтверждает `primaryDoor` только у H016; H009 не изменён. Чтобы повторная диагностика не смешивала старый StreetDoor с новым access, оба кандидата теперь вычисляют свой подход от собственной геометрии, а выбранный production leaf и registryAccess записываются отдельно. Схема receipt2, labels `existing-street-door` / `existing-seni-door`. Поле `approachReachable` доказывает опору и прямой путь; LOS/range к временной надписи не подменяются этим фактом и явно отмечены как ещё не проверенные.

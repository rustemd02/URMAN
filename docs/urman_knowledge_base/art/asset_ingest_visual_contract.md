# Контракт приёма скачанного пропа (VIS-106)

Дата: 2026-10-07. Внешний ассет попадает в игру только как нормализованный член семейства УРМАНА,
не как «салат из ассет-паков». Порядок обязателен; каждый пункт проверяется статически
`tools/asset_generation/check_prop_ingest.py <file.glb> --rebind <map.json>` (движок не нужен).

Уточнение продолжения 07.10: скрипт проверяет выбранный файл и описание перепривязки,
но не изменяет GLB и не применяет карту в runtime. Приёмник должен явно исполнить
привязки через указанную библиотеку. Скрипт не заменяет VIS-107 и человеческую
проверку лицензии; геометрический gate отклоняет skins, morphs и GPU instancing,
пока они не запечены в статический проп. Пустая сцена или повреждённый GLB — FAIL.
Наличие `externalAsset: true` само по себе больше не проходит provenance:
проверяются поля лицензии/источника/автора/правок, существование consumers,
хеш производного GLB и доступного локального оригинала, кадр для integrated.

Квитанция VIS-108 теперь имеет схему `urman.glb_structure_receipt.v2`: индексы
и родители узлов, матрицы, сцены, POSITION bounds и режим примитива. Старые
13 квитанций v1 сохранены как история; переснять v2 при следующей разрешённой
пересборке. Новые инструменты в этом продолжении не запускались: только разбор
синтаксиса. A/B приёмка, первый прошедший ingest проп и детерминированная
повторная Blender-пересборка остаются невыполненными, VIS-106/108 — PARTIAL.

| # | Поле | Требование | Чем проверяется |
|---|---|---|---|
| 1 | Лицензия и провенанс | запись в `assets/asset_registry.json` с `externalAsset: true`, SPDX из белого списка, https-источник, автор, правки, consumer | `check_prop_ingest.py` (provenance) + `eng/verify-asset-registry.sh` (VIS-107) |
| 2 | Масштаб | метры; наибольший габарит 0,02–12 м (иначе явный `--min/--max`); иерархия и TRS/matrix default scene учтены | scale |
| 3 | Пивот | низ трансформированного AABB на высоте начала координат (±5 см); после поворота оценка консервативна, точный контакт требует кадра | pivot |
| 4 | UV | `TEXCOORD_0` типа VEC2 у каждого примитива; count совпадает с POSITION | uv |
| 5 | Слоты материалов | 1–4, уникальные непустые имена, все примитивы имеют назначенный слот | slots |
| 6 | Свет | никаких встроенных `KHR_lights_punctual` | lights |
| 7 | Камеры | никаких | cameras |
| 8 | Анимации | удалены, если не нужны (`--allow-animation` — только с причиной) | animations |
| 9 | Треугольники | 1–6000 на проп; повторные экземпляры в default scene и strips/fans учитываются; линии/точки не принимаются | triangles |
| 10 | Перепривязка материалов | каждый исходный слот → `rrggbb|surface` для PainterlyMaterialLibrary либо `rrggbb|rural:kind` для RuralPropMaterials; имя берётся из действующего кода | rebind |
| 11 | LOD / коллизия | владелец коллизии назначен в коде (простая форма), LOD — если видим дальше 15 м | ревью кода |
| 12 | Кадр | runtime-кадр приёмника в интерьере/экстерьере A/B, `receiverCapture` в реестре | станция (VIS-107 `integrated`) |

## Нормализация

- Убрать встроенный свет, камеры, лишние анимации и пустые узлы до экспорта.
- Перенести пивот в основание, применить масштаб (1 единица = 1 м).
- Материалы перепривязать к семейству УРМАНА: металл по VIS-095 (краска `metallic 0`, голый металл `1`),
  дерево/ткань/пластик — существующие painterly-семейства; собственные текстуры автора ассета допустимы
  только как альбедо в UV, без Substance-вида (VIS-092).
- Структуру GLB зафиксировать квитанцией `tools/blender/glb_structure_receipt.py` (VIS-108).

## Найдено при введении (2026-10-07)

Пропсы полицейского участка (`game/assets/third_party/police/*.glb`) имеют провенанс в собственном
`manifest.json`, но **нет записей в `assets/asset_registry.json`** → проверка provenance падает.
`desk_lamp_arm_01.glb` — 7230 треугольников при бюджете 6000. Перенести записи в реестр (с
`externalAsset: true`) и решить бюджет лампы — отдельная задача; интегрированный вид не менялся.

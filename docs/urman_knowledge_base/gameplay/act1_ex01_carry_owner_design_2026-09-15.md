# EX01 — дизайн Godot-владельца переноса/размещения (срез перед кодом)

Дата: 2026-09-15. Срез: `73ff33d` + правки EX00. Заполняет Godot-половину контракта EX00
(`act1_ex00_state_contract_design_2026-09-15.md`): владение/claims — `CustodyStore`, этот документ —
мировая половина (трансформы, визуал held, ввод, размещение).

## Владелец изменения

| Слой | Владелец |
|---|---|
| Владение/claims/событие | `CustodyStore.PlanBatch` (`world.custody`), вызывается новым хендлером в `RuntimeBridge.CreateHandlers()` рядом с `world.interact` |
| Визуал/физика предмета | новый `game/scripts/CarryableProp.cs` (компонент на корне предмета) |
| Координатор (hold point, луч, промпт) | `game/scripts/CarryCoordinator.cs` (Node у Main, рядом с плеером) |
| Ввод | существующее действие `interact` (контекстное взятие/кладка) + новое remappable `carry_rotate` |
| Сохранение | существующий `SaveGameV3.Runtime` snapshot — позиции/флаги предметов пишутся хендлером в состояние ядра |

Ничего из существующих владельцев не забирается: находки, калитки и сюжетные предметы остаются у своих
владельцев; переносимыми становятся только новые предметы, специально помеченные.

## Состояние предмета (машина)

- `world` — лежит в авторской точке; InteractionTarget активен, промпт «Взять».
- `held` — прикреплён к hold-точке перед камерой (0,45 м, ниже взгляда на 0,15); коллизия предмета
  выключена, промпт «Положить [сюда] / Повернуть».
- `placed` — лежит в точке кладки (привязка к полу через `CollisionGround`), коллизия включена;
  повторное применение — снова взять.

Переходы: `world→held` (interact у предмета), `held→placed` (interact при валидной точке),
`held→world` (отмена: пройти слишком далеко от допустимой поверхности — предмет мягко падает
обратно в руки... нет: предмет возвращается в последнюю валидную точку), `placed→held` (снова взять).
Повторное применение работает циклически без сброса.

## Валидация кладки (T1-совместимо)

- Луч вниз из точки перед камерой → `CollisionGround` для высоты; наклон поверхности ≤ ~25°.
- Проверка объёма: `IntersectShape` капсулой предмета против статической геометрии — пересечение
  запрещает кладку (промпт краснеет).
- Запрет зоны: не на дороге (RoadInfo), не в метре от карточек/документов, не в объёме НПС.

## Три класса вещей EX01 (все — новые простые меши у двора героя, без новых ассетов)

| Класс | Предмет | Размер/масса-поведение | Место авторской точки |
|---|---|---|---|
| Лёгкий (одна рука) | полено из поленницы | 0,35×0,12; держится ближе к камере | геройский двор, у поленницы |
| Средний (две руки) | деревянный ящик | 0,45×0,35×0,35; держится ниже, поворот шагом 15° | геройский двор, у сарая |
| Наливной (ведро) | ведро с «водой» | уровень воды виден, при быстром переносе расплёскивается (частицы) | геройский двор, у крыльца |

Повторное применение: каждый класс берётся/кладётся неограниченно; ведро после «расплёскивания»
меняет уровень воды (сеансовое состояние, не сохраняется — честно помечено).

## Сохранение (через существующий snapshot)

Хендлер `world.custody` пишет в состояние ядра: `items: [{itemId, state, x, z, yaw}]`. `RestoreSession`
после загрузки вызывает `CarryCoordinator.ApplySnapshot` — предметы расставляются по сохранённым
позициям. Новый сеанс — авторские точки. Ничего в `Node metadata` источником не является.

## Ввод

- `interact` — взять/положить (контекстно).
- Новое remappable `carry_rotate` (по умолчанию R / геймпад X) — поворот в руках до кладки; добавляется
  в `InputBindingService.RemappableActions` и в input-map проекта с дефолтом.

## Верификация карточки (по §9.1)

Действие → повтор → загрузка → новый сеанс, всё обычным управлением: взять у поленницы, пронести до
крыльца, положить, взять снова, положить в другое место; сохранение/загрузка воспроизводит позицию;
новый сеанс возвращает авторские точки. Плюс: walkthrough PASS (без регрессии маршрута), физический
контакт (предмет не проваливается, не парит).

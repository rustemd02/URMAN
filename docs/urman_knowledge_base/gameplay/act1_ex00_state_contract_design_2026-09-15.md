## EX00.2 — управление (первый кандидат)

- В руках один крупный предмет: «взять/положить» (контекстное действие у предмета), «использовать
  инструмент» (предмет определяет действие), «отменить размещение» (до фиксации), «повернуть»
  (перед размещением). Все — через существующий remap; свободного броска нет.
- Ни одно новое действие не вешается на нажатие, которое уже закрывает журнал.

## EX00.3 — состояния предмета

- `world` → `held` → `placed` (+ `combined` для EX04). Для каждого: владелец (runtime state),
  допустимые применения, постоянство положения (да для размещённых, сеансовое для удержания).
- Позиция сохраняется в snapshot вместе с флагом «в руках» → после загрузки предмет восстанавливается
  в руках либо в записанной безопасной точке рядом. Инвалидная точка — доступная точка возврата предмета.
- Прогресс/знания — по-прежнему только runtime knowledge; Node metadata и UI-переменные источником не являются.

## EX00.4 — переходы и совместимость

- Сохранение при «в руках»: логическое владение сохраняется, удержание после загрузки — по контракту
  каждой вещи (в руках у двери; на безопасной постановке в мире).
- Смена версии формата: фактическая политика проекта — не ломать сохранения молча; изменение
  fingerprint контента фиксируется в карточке с результатом совместимости.
- Дубликат вещи, потерянный инструмент или повторная награда — провал приёмки.

## Подтверждение EX00 (2026-09-15): реальный потребитель CustodyStore проверен

`CustodyStore` (`src-dotnet/Urman.Core/World/CustodyStore.cs`, 191 строка) — чистый планировщик
состояния: `PlanBatch(state, operations, claimOwnerId, claimLifecycleScope)` читает список предметов
(`itemId` + `custodyOwnerId`), применяет операции `acquire`/`transfer`/`consume` с проверкой владельца,
возвращает `CommandPlan` (новое состояние + claims владения + событие `world.custody.changed`).
Детерминирован, без зависимости от Godot.

**Найдено и зафиксировано:** продакшн-потребителя нет — единственный вызывающий это юнит-тест
`tests-dotnet/Urman.Core.Tests/WorldPrimitivesTests.cs:51`. Игра никогда не вызывает `PlanBatch`, ни одна
запись definitions не пишет состояние `world.custody`, в `RuntimeBridge.CreateHandlers()`
(`RuntimeBridge.cs:937-942`, обработчики `world.interact`, `oldpc.*`, `quest.lifecycle`) хендлер custody
не зарегистрирован. Подозрение плана подтвердилось полностью.

**Пригодность для EX01+:** модель подходит как слой владения — предметы с владельцем
(«мир» ↔ актёр), операции acquire/transfer/consume, claims для учёта. Чего в ней нет и что остаётся
за Godot-владельцем: мировые трансформы размещённых предметов, визуал предмета в руках, ввод.

**Точка подключения, когда EX01 будет поручена:** регистрация хендлера в `RuntimeBridge.CreateHandlers()`
рядом с `world.interact` (строка 938) — `handlers.Add("world.custody", ...)` → `CustodyStore.PlanBatch`;
состояние `world.custody` попадает в snapshot ядра и сохраняется существующим `SaveGameV3.Runtime`
без второго пути сохранения.

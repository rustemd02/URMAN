# Проектные реестры, не готовый runtime-контент

JSON-файлы предназначены для переноса требований в действующий компилятор контента URMAN. Их поля и команды не объявлены совместимыми с текущими C#-типами. Агент пишет явный адаптер, валидацию схемы и тесты, а не загружает эти файлы в релиз вслепую.

`tasks.spec.json` — 100 карточек со связями. `assets.spec.json` — 48 семейств производства, а не 48 готовых объектов. `photos.spec.json` — 13 снимков, в том числе пять проходных. `worlds.spec.json` — локальные графы пяти новых сцен. `campaign.spec.json` — абстрактные логические условия, не доказанный игровой граф. `dialogues.spec.json` — рабочий русский текст; татарский перевод требует проверки. `legacy_118_migration.json` сохраняет исходный текст каждой прежней задачи как историю и задаёт её преемника. Старый текст внутри этих записей не отменяет новый мандат.

Проверка: `python tooling/validate_spec.py --self-test`. Результат относится только к целостности спецификации. Начальные статусы производства, запуска игры и авторской приёмки намеренно не содержат PASS.

При изменении PRODUCTION_DEFAULT синхронно обновлять JSON, соответствующий Markdown, условия зависимых задач и тестовый план. AUTHOR_FIXED без нового распоряжения автора не менять.

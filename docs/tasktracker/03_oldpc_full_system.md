# 03. ПК бабая — полная система v2 (чат, подсказки, браузер, тетрис, файловая система)

> Статус: ТЗ принято 2026-09-18. Решения автора (опрос 2026-09-18): интерфейс — **гибрид desktop + глобальный поиск**;
> чат — **живой чат с NPC + контекстные подсказки по прогрессу**; глубина — **30+ документов, в которых можно утонуть**;
> тетрис — **чистая пасхалка без связи с сюжетом и лором**.
> Канонные замки из `docs/urman_knowledge_base/old_pc.md` (product lock 2026-05-18) действуют полностью:
> безымянная Win98-like оболочка, ПК — документальный хаб расследования, accessConditions — единственный владелец знаний,
> максимум один оправданный пароль (предпочтительно татарское слово), технические метаданные — не улика,
> пакт доказывается, но не объясняется. Деревня — **КАРА-УРМАН**, герой — **Айдар** (решение 2026-09-18).

## 0. Что уже есть (база, не переписывать)

- Окна desktop: `archive`, `files`, `browser`, `notepad`, `writer`, `pictures`, `trash` — drag, focus/z-order,
  taskbar, «Пуск», часы, save/load снапшота (`OldPcDesktopSnapshot`, схема `oldpc-state.schema.json`).
- Архивный keyword-поиск + подсказанные термины, gated-документы, повреждённые фрагменты, отметка `✓` прочитанного,
  строка «🔒 Закрытые записи» без metadata (правило нераскрытия закрытых заголовков — святое).
- Браузер: `home / tatwiki.local / yalkyn.local / kara-urman.local / mail.local`, история (64), внутренние ссылки `doc:`.
- Соцсеть «Ялкын» — только чтение (профили/посты/комменты из markdown), сохранённые сообщения Марата — только архив.
- Контент: ~40 файлов в `content/modules/urman-oldpc/documents/`, суммарно ~4600 слов — **тонко**, это и чиним.
- Нет вообще: живого чата, системы подсказок, глобального поиска, тетриса.

## 1. Цели и не-цели

Цели: ПК — место, где залипают на час: живой чат, честные подсказки, глубокий браузер, 30+ перекрёстных документов,
удобная файловая система, тетрис-пасхалка. Всё data-driven: новый `.md`/тред/хинт добавляется без правки кода.

Не-цели (запрещено): настоящая ОС, терминал, свободный взлом, сложные пароли, tech-метаданные как улики,
новые сообщения от Марата (он мёртв — только сохранённый архив), раскрытие пакта в любом приложении ПК,
лор-награда за тетрис (решение автора: пасхалка чистая), GPS-подсказки с метками на карте мира.

## 2. Оболочка: гибрид desktop + глобальный поиск

2.1. Desktop остаётся Win98-like безымянным. Новые приложения в ярлыках, «Пуске» и панели задач:
`chat` («Ялкын · Сообщения»), `tetris` («Тетрис»). Всего окон desktop: 7 → 9.
2.2. Глобальный поиск: поле поиска в меню «Пуск» + кнопка «Искать везде» в архиве. Один запрос ищет сразу по:
доступным документам (заголовок+тело), истории чатов (доступные треды), личным заметкам, заголовкам истории браузера.
2.3. Правила выдачи (наследуют правило архива): закрытые документы/треды не участвуют в выдаче вообще;
одна невыбираемая строка «🔒 Закрытые записи»; ноль результатов — «переформулируйте запрос» + 3 подсказанных термина;
татарские слова — кнопки-ключи. Поиск никогда не даёт знания: клик по результату идёт через обычный
`IsOldPcDocumentAccessible` / гейты тредов.

## 3. Живой чат «Ялкын · Сообщения»

3.1. Треды только с живыми: **Алсу**, **Ринат** (тред открывается после `rinat.alerted=true` — того же условия,
что открывает сохранённое сообщение Марата), **бабай Мансур** (бытовая линия + первая сцена доступа к ПК, §5 old_pc.md:
просьба помочь с компьютером — теперь это первое сообщение треда, а не катсцена).
Марат — только read-only экспорт старого лога, ответить нельзя (UI явно пишет «архив, ответить нельзя»).
3.2. Механика: входящие — скриптованные реплики из данных (не свободный ИИ-чат). Игрок отвечает выбором из 2–3
вариантов ответа (как диалоги мира, но внутри ПК) + свободный текст, на который приходит честный заглушечный ответ
(«Мансур не понял, переспроси позже») — свободный текст никогда не двигает сюжет, двигают только варианты.
3.3. Триггеры входящих: knowledge-статусы / npc.state / открытые документы (те же accessConditions, data-driven:
`requires` + `reveals`). Непрочитанные — счётчик на иконке чата и в таскбаре. Presence честный: «был(а) недавно»,
«не в сети» — без фейковых «печатает…» дольше 3 секунд.
3.4. История треда хранится в снапшоте (bounded: тредов ≤ 4, сообщений на тред ≤ 64, текст ≤ 500 знаков),
переживает save/load/new-game-ветки без дублей. Удаление треда — только в корзину как у заметок? Нет:
треды не удаляются (это чужие люди), можно только «свернуть».
3.5. Чат никогда не выдаёт закрытые документы целиком: NPC может дать только search term / намёк
(см. §4), а документ игрок находит сам через поиск — петля «запрос → документ → противоречие → ключ» не рвётся.

## 4. Контекстные подсказки

4.1. Два носителя: (а) системный тред «Заметки Айдара» (разговор с собой — внутримирово честно: Айдар фиксирует мысли);
(б) строка-подсказка в архиве при нулевой выдаче и после 3 безрезультатных запросов подряд.
4.2. Подсказки трехуровневые, data-driven (`hints/*.md` или секция документа `hint:`): уровень 1 — толчок
(«спроси Наилю про реестр»), уровень 2 — направление («внутренний учёт противоречит справке — сравни даты»),
уровень 3 — почти прямой ответ, но никогда не цитата закрытого документа и никогда раньше его `requires`.
4.3. Правила gating: хинт виден только если выполнены его `requires` (те же knowledge/npc/document-условия);
хинт не создаёт knowledge-ключи и не пишет в журнал сам — он только ведёт к месту, где игрок сам находит улику.
Уровень 3 открывается только после ≥2 открытых Tier-A документов (игрок уже в теме, не спойлерим новичку).
4.4. Состояние «какие хинты показаны» — в снапшоте (`hintsSeen: [ids]`, bounded ≤ 64), переживает load без повторов.

## 5. Браузер и соцсеть: глубина

5.1. Сохранить 5 узлов (home/tatwiki/yalkyn/village/mail), наполнить каждый минимум до:
TatWiki — 8 статей (Шүрәле/урман-кромка обязательны как gameplay-ядро; остальные существа — боковые, без раздувания MVP);
«Ялкын» — 6 профилей + 2 сообщества с комментариями; сайт авыла — стилизация 2008–2012 (счётчик, гостевая книга,
фото Сабантуя, старые новости); почта — 6 писем/черновиков; home — хаб со ссылками.
5.2. Каждая страница: внутренние ссылки на ≥2 связанных материала, минимум 1 ссылка — на документ из другого узла
(сеть, а не линейка). Битые/закрытые ссылки рендерятся как «Раздел пока недоступен» (существующий рендер сохранить).
5.3. «Татарвики» читается сначала как фольклор, к финалу — как завуалированная инструкция по выживанию;
ни одна статья не объясняет пакт прямо (замок old_pc.md §«Татарвики»).

## 6. Файловая система и 30+ документов

6.1. Структура «Моего компьютера»: `C:\Мои документы\{Заметки Айдара, Фотографии, <9 архивных разделов из old_pc.md>}` —
без изменений, добавляются только новые файлы внутрь. Личные заметки (32 шт / 32К знаков) и корзина с восстановлением —
как есть.
6.2. Контент-план (минимум, каждый файл — frontmatter по §9 + тело):
Tier A — расследование, ≥350 слов каждый (12): официальная справка Марата (есть, углубить), конфликтный реестр
(есть, углубить), внутренняя запись 1987 (есть, углубить), повреждённый учёт (есть, углубить), кромка Кара-Урмана
(есть, углубить) + новые: протокол сельсовета о «компенсации», письмо из Казани (есть-скелет → полный текст),
школьная тетрадь Марата стр. 41 (углубить), медкарта Марата (фон уже есть как asset — дописать документ),
объяснительная Фаниса, список «ответивших» 1970-х (повреждённый), схема зиратских обычаев (есть → связать с Маратом).
Tier B — быт/контраст, ≥150 слов (10): квитанции за свет, урожайная тетрадь, каталог семян, радиолог Нивы,
квитанция Нивы, подписи на коробках с фото, реестр дома линии Г/Ф/М (есть-скелеты → полные), письмо из Казани бытовое.
Tier C — сеть, короткие связанные (10+): профили Мансура/Алсу (есть → углубить), сообщество «Наш авыл» (есть),
школьный альбом Фариды (есть), гостевая книга сайта, 3 старых новости авыла, 2 письма в почте, черновик Мансура
(есть как unsent note → связать).
6.3. Каждый Tier-A документ: `searchTerms` ≥ 5 (включая ≥1 татарское слово), `suggestedTerms` ≥ 2,
`reveals`/`requires`/`unlocks` залинкованы (цепочки: ≥6 документов открываются только через другие документы/слова/разговоры),
`reliability` + `canonStatus` обязательны, перекрёстные markdown-ссылки `[текст](doc:id)` на ≥2 связанных.
6.4. Gating-цепочки (пример, автор правит): справка Марата открыта сразу → реестр противоречий требует
`contradiction_marat_official_vs_internal` + Наилю (`naila.record_access_granted`, замок 2026-09-13) →
сохранённое сообщение Марата требует противоречие + `rinat.alerted` → внутренняя запись 1987 требует сообщение →
«ответившие 1970-х» требуют запись 1987 + татарский ключ. Один пароль максимум на весь ПК (если нужен —
татарское слово из разговора, не дата с могилы).
6.5. Бытовые папки — ложные следы и контраст, не конкуренты расследованию (замок old_pc.md). Ни один бытовой
документ не требует Tier-A гейтов и не выдаёт ключей Tier-A.

## 7. Тетрис (чистая пасхалка)

Полноценный играбельный тетрис: стакан 10×20, 7 фигур, уровни/скорость, пауза, управление стрелками + Z/X/пробел/P,
кнопки мышью для тех же действий. Рекорд — единственное персистентное поле (`tetrisHigh`, int 0…999999, в снапшоте).
Середина партии не сохраняется (закрыл окно — партия сгорела, рекорд остался). Пауза при сворачивании/потере фокуса.
ЯВНЫЙ ЗАПРЕТ: рекорды/счёт/сыгранные партии не открывают документы, реплики, хинты и journal-записи; тетрис не участвует
в глобальном поиске; в коде — отдельный UI-класс без доступа к knowledge-шине (только чтение `tetrisHigh`).

## 8. Удобство (чтобы реально залипать и было удобно)

8.1. Окна: drag за заголовок, double-click — maximize, Alt+Tab, таскбар, сворачивание; состояние всех окон живёт в сейве.
8.2. Читаемость: крупный шрифт, high-contrast тема и text-scale применяются ко всем новым окнам (чат/тетрис/поиск)
через существующие `ApplyDesktopAccessibility`/`ApplySocialPresentation` — новые контролы туда вписать, а не плодить свои.
8.3. Журнал в обе стороны: важные документы — автоключи (существующие openEffects), ручное «В книжку» из браузера/архива —
как есть; из чата в книжку сохраняется только search term/цитата NPC по кнопке «Записать» (идёт как обычная выписка,
не как знание). Отметка `✓` прочитанного — везде, включая чат-треды и страницы браузера.
8.4. Часы ПК идут от `ElapsedSeconds` (как есть). Звук: существующий UiFoley на кнопки/окна; для тетриса — те же клики,
без новой музыки (нет аудиовхода для проверки — не закапываться).

## 9. Данные и схемы (data-driven контракт)

9.1. Новые документы — те же `.md` с frontmatter в `content/modules/urman-oldpc/documents/` + регистрация
в `module.json` (`sourceFiles` + `provides`). Обязательные поля (замок old_pc.md §Data-Driven):
`id, type, title, pcSection, canonStatus, reliability, searchTerms, reveals, requires, unlocks,
relatedCharacters, relatedLocations, dangerLevel, mvp`.
9.2. Чаты: `content/modules/urman-oldpc/chat/{alsu,rinat,babay,self}.md` — frontmatter
(`id, requires, presence`) + тело: скрипт реплик и вариантов ответа игрока с `reveals` (только terms/хинты, не документы).
Свободный текст игрока — без ветвлений, ответ-заглушка из данных.
9.3. Хинты: `content/modules/urman-oldpc/hints/*.md` — (`id, level 1–3, requires, pointsTo` (куда ведёт, не что раскрывает),
текст ≤ 300 знаков). Валидатор контента расширить на chat/hints (закрытые id не светятся, ссылки только на существующие id).
9.4. Снапшот/схема (`OldPcDesktopSnapshot.cs` + `oldpc-state.schema.json` + provider-валидация — менять только вместе):
`Applications += ["chat", "tetris"]`, окон max 9; `chat: {threads ≤4: {id, messages ≤64 × ≤500 знаков, unread}}`,
`hintsSeen ≤ 64 ids`, `tetrisHigh 0…999999`. Миграция старых сейвов: неизвестные id окон → отбросить, отсутствующие
новые поля → дефолты, никогда не крашить load. Лимиты показать в UI честно (32 заметки, 64 сообщения треда).

## 10. Журнал, сейвы, границы знаний

10.1. Единственный владелец знаний — authored `accessConditions` + старый OldPc-провайдер (замок ACT1-OLDPC).
Чат/хинты/поиск/тетрис не получают своих шин знаний и не пишут knowledge напрямую.
10.2. Save/load/new-game/повтор/отказ/возврат: без дублей сообщений/хинтов/заметок, без преждевременного прогресса,
закрытые треды/документы не мелькают ни в одном UI (чат-лист, поиск, история браузера, «Недавние»).
10.3. compiiled-контент (`game/content/*.compiled.v1.json`) пересобирается штатным `eng/compile-game-content.sh`;
ручные правки compiled-файлов запрещены.

## 11. Проверки приёмки (без человека, без Windows)

11.1. На каждую задачу §12 — smoke на точной текущей сборке через `eng/protected_run.py`
(desktop/chat/hints/search/browser/tetris/docs/save-load), evidence — в `docs/production/act1_takeover_evidence_2026-09-16/`,
guard после прогона восстановлен, пользовательские saves/preferences не затираются.
11.2. Критерии живого ПК (расширяют acceptance old_pc.md): игрок открывает ПК из дома → делает свой запрос
в глобальном поиске → находит документ Марата → открывает gated/повреждённый → получает хинт 1 уровня и сам доходит
до улики → clue меняет разговор с NPC → татарское слово работает ключом → час в ПК (чат+доки+тетрис) без тупиков
и без преждевременных знаний. Пакт почувствован, не объяснён.
11.3. Очередь и матрица: `execution_backlog.json` + acceptance matrix обновляются тем же изменением, что и код.

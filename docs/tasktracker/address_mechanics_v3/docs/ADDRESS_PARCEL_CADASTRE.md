# Address, parcel and cadastral-like mechanics

## Главное разделение

### Building
Физический объект в мире.

### Parcel
Земельный участок, на котором может быть:
- основной дом;
- сарай;
- баня;
- гараж;
- летняя кухня;
- несколько связанных построек.

### Address
Адресная запись. Она описывает, как объект ищет человек.

### Stable IDs
Нужны машине.

Эти вещи не следует объединять в одно поле.

---

## Stable references

Пример:

```json
{
  "building_id": "BLD-4FGX8W...",
  "parcel_id": "PAR-01J...",
  "address_id": "ADR-0HT...",
  "display_address": {
    "street_id": "tukay",
    "house_number": "17"
  },
  "game_cadastral_id": "URM-Q01-P0017"
}
```

Квест:
`go_to_building_id = BLD-...`

НЕ:
`go_to_address = "Тукай 17"`

Тогда переименование улицы ничего не ломает.

## Нумерация домов

### Направление
Каждая улица получает `origin`.
Обычно это:
1. её узел с главной улицей;
2. если она не соединяется напрямую — ближайший узел к центру;
3. для главной — главный въезд / исторический центр.

`chainage` растёт от origin.

### Стороны
Для каждого addressable entrance:
- вычислить ближайший street segment;
- взять tangent улицы;
- cross product определяет left/right.

На одной стороне идут нечётные, на другой чётные.
Какая именно сторона odd — фиксируется в `street.numbering_side`, а не пересчитывается каждый запуск.

### Existing numbers
Если номер уже авторски выставлен:
- сохранить;
- проверить конфликт;
- не пытаться «исправить» только потому, что последовательность неидеальна.

Старые деревни имеют пропуски и исключения.

### Infill
Новый дом между 7 и 9:
сначала использовать `7А`, `7Б` и т.п., а не перенумеровывать всю улицу.

### Corner building
Приоритет:
1. explicit entrance;
2. driveway/gate;
3. главный фасад;
4. nearest street как fallback.

Это близко к реальной адресной логике, где объект на пересечении относится к улице фасада.

## Несколько строений на одном участке

Не выдавать номер каждому сараю.

Пример:
- parcel `URM-Q02-P0037`
- main house: `ул. Лесная, 12`
- garage: address inherited, `subbuilding_role=garage`
- bathhouse: inherited
- второй самостоятельный жилой корпус: можно получить `12 к1` только если геймдизайн реально требует отдельной адресуемости.

## Game cadastral IDs

Российская система реально разделяет территорию на кадастровый округ → район → квартал → объект.

В игре использовать **свою hierarchy**, например:

- `URM` — namespace мира
- `Q03` — игровой кадастровый квартал
- `P0041` — parcel serial

Получаем:
`URM-Q03-P0041`

### Почему не `16:xx:xxxxxx:xxx`

Такой формат слишком похож на настоящий кадастровый номер.
Вымышленная игра может случайно воспроизвести реально существующий объект.
Поэтому legal-looking colon format не использовать как production default.

Если нужна внутриигровая бумага «под Росреестр», Astra может стилизовать поле визуально, но источник данных всё равно `game_cadastral_id`.

## Quarter generation

Если карта уже имеет районы/кварталы — сохранить.

Иначе:
- разделить поселение по сильным edges и road branches;
- каждый parcel принадлежит ровно одному game quarter;
- quarter boundaries не должны резать parcel;
- quarter IDs стабильны после первого commit.

Нельзя пересчитывать Q01/Q02 при каждом seed после выхода игры.

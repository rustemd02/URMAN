# URMAN — ТЗ на доработку игры

**Приоритет требований с 28.09.2026:** [авторский разбор](review_2026-09-28/README.md) и текущие контракты
`execution_backlog.json` пересматривают явно отмеченные требования этого документа. Остальное сохраняется.
Persona, uncanny всего каста, квоты слов/применений и прежние автоматические команды продолжения не действуют как новые
критерии. Старые evidence/выполненные части ниже — история, не приёмка нынешнего отзыва. Сейчас только документация,
долгая игровая работа на авторской паузе; не запускать новую реализацию из исторического launch prompt.

Документ описывает желаемые механики, транспорт, ключевые здания и общую структуру деревни.

Перед реализацией каждого крупного блока необходимо:
- сначала проверить, что уже существует в текущем коде;
- изучить подходящие решения для текущего движка;
- не создавать вторую параллельную систему, если аналог уже есть;
- выбирать простую и расширяемую архитектуру;
- использовать placeholder-графику там, где финальный визуал ещё не готов.

---

# 1. Игрок и управление

Нужно добавить или довести до нормального состояния:

- прыжок;
- приседание;
- ходьбу;
- более быстрое перемещение;
- видимые ноги и нижнюю часть тела;
- нормальные коллизии;
- адекватное движение камеры.

При взгляде вниз игрок должен видеть собственное тело.

Приседание должно реально уменьшать collider персонажа, а не просто опускать камеру.

Прыжок должен учитывать grounded state.

### Перед реализацией изучить

- как сейчас устроен Player Controller;
- CharacterController / Rigidbody / существующую физическую систему;
- current Input System;
- existing animation controller;
- правильные способы реализации first-person body awareness;
- как избежать clipping тела через камеру;
- как синхронизировать crouch с collider.

Не переписывать Player Controller целиком без необходимости.

---

# 2. Взаимодействия и стук в двери

Нужно убрать механику, когда стук автоматически происходит при приближении к зданию.

Новое поведение:

1. игрок подходит к двери;
2. дверь определяется системой взаимодействий;
3. появляется минимальный feedback;
4. игрок сам нажимает кнопку взаимодействия;
5. только после этого происходит стук.

Разные двери могут иметь разные действия:

- открыть;
- постучать;
- заперто;
- войти;
- позвонить.

### Перед реализацией изучить

- существующий interaction system;
- triggers около домов;
- OnTriggerEnter / OnTriggerStay;
- raycast interactions;
- существующие Door / House scripts;
- откуда сейчас вызывается звук стука.

Желательно сделать одну понятную систему взаимодействий для дверей, предметов, компьютера, транспорта и документов.

---

# 3. Адресная система деревни

Авыл должен иметь настоящую логичную адресную структуру.

Нужно:

- названия улиц;
- номера домов;
- адресные таблички;
- логичную последовательность нумерации;
- возможность использовать адреса в заданиях;
- возможность NPC давать игроку адрес словами.

Пример:

«Тукай урамы, 17 йорт».

Игрок должен реально искать нужный дом по улицам и номерам.

Не использовать постоянную GPS-стрелку до цели.

Адреса должны сохраняться в записной книжке.

### Перед реализацией изучить

- как реально нумеруются дома в татарских деревнях;
- структуру улиц и переулков;
- типичные двуязычные адресные таблички Татарстана;
- как лучше хранить адреса data-driven;
- как связать адрес с конкретным House ID.

Желательно, чтобы каждый важный дом имел внутренний уникальный ID независимо от отображаемого адреса.

---

# 4. Записная книжка

Записная книжка — основной информационный интерфейс игрока.

Разделы:

- люди;
- адреса;
- заметки;
- задачи;
- места;
- наблюдения.

Она должна выглядеть как настоящая личная записная книжка.

Не делать стандартный RPG Quest Log.

Новые сведения должны постепенно добавляться по мере исследования мира.

Например:

NPC сообщил адрес → адрес появился в разделе «Адреса».

Игрок нашёл фамилию на старой фотографии → информация добавилась к персонажу.

### Перед реализацией изучить

- существующую notebook/journal систему;
- save/load;
- data-driven journal entries;
- удобную навигацию между страницами;
- diegetic UI;
- варианты отображения физической книжки перед камерой.

---

# 5. Компьютер бабая

Компьютер должен быть отдельной большой интерактивной системой.

Стиль:

Windows XP / домашний компьютер 2000-х.

Нужно:

- рабочий стол;
- фон;
- панель задач;
- часы;
- меню наподобие «Пуск»;
- ярлыки;
- папки;
- файлы;
- корзина;
- окна.

Программы:

- аналог Notepad;
- аналог Word;
- File Explorer;
- браузер;
- просмотр изображений.

Часть интерфейса на татарском, часть на русском.

Смесь языков должна выглядеть естественно.

### Перед реализацией изучить

- как реализовать desktop/window manager внутри игрового UI;
- existing UI framework проекта;
- draggable windows;
- focus/z-order;
- fake filesystem;
- хранение документов и изображений;
- сохранение открытых/найденных файлов.

Не нужно делать настоящую операционную систему.

Нужна только убедительная симуляция.

---

# 6. Интернет бабая

Через компьютер игрок получает доступ к локальному внутриигровому интернету.

Минимум:

### TatWiki

Локальная энциклопедия.

Материалы:

- деревни;
- история района;
- люди;
- культура;
- местные названия;
- легенды;
- Шурале;
- старые события.

### Местная социальная сеть

Профили жителей и старые записи.

Можно показывать:

- фотографии;
- комментарии;
- поздравления;
- посты;
- обсуждения;
- старые сообщества.

### Дополнительно

- старый сайт деревни;
- местные новости;
- почта;
- история браузера;
- старые фотографии;
- документы.

Отдельно можно сделать старый сайт деревни примерно 2008–2012 года:
- плохой дизайн;
- счётчик посещений;
- фотографии Сабантуя;
- гостевая книга;
- старые новости.

### Перед реализацией изучить

- data-driven web pages;
- простую внутреннюю систему ссылок;
- reusable browser UI;
- хранение статей и постов;
- возможность добавлять новый контент без изменения кода.

Настоящий интернет не нужен.

---

# 7. Старая Нива

Нива — основной транспорт по деревне.

Использование:

- дом бабая;
- магазин;
- мечеть;
- школа;
- ФАП;
- сельсовет;
- другие части авыла.

Нужно:

- сесть;
- выйти;
- завести;
- ехать;
- тормозить;
- фары;
- нормальный звук двигателя;
- интерьер;
- радио.

Машина должна ощущаться старой и бытовой.

Не делать аркадную GTA-физику.

### Перед реализацией изучить

- существующую vehicle system;
- подходящую автомобильную физику для движка;
- WheelCollider или используемый в проекте аналог;
- enter/exit vehicle;
- camera switching;
- collision;
- парковку;
- сохранение позиции транспорта.

Физика должна быть достаточно простой и стабильной.

---

# 8. Мотоцикл

Мотоцикл — более быстрый и свободный транспорт.

Назначение:

- быстро перемещаться по деревне;
- ездить по полевым дорогам;
- просто кататься.

Можно использовать старый советский/постсоветский мотоцикл соответствующего периода.

### Перед реализацией изучить

- управление двухколёсным транспортом;
- баланс между реалистичной и удобной физикой;
- возможность использовать общую систему транспорта от Нивы;
- посадку/выход;
- камеру.

Не создавать отдельную архитектуру транспорта с нуля, если можно использовать общий Vehicle Base.

---

# 9. Лошадь и телега

Телега используется прежде всего для поездок в лес.

Это важный атмосферный транспорт.

Нужно:

- лошадь;
- телегу;
- управление;
- возможность сесть и выйти;
- движение по лесным дорогам;
- отдельный звук колёс, дерева и копыт.

Лошадь должна реагировать на происходящее.

Например:

- нервничает;
- замедляется;
- останавливается;
- не хочет идти дальше.

Это можно использовать как индикатор присутствия чего-то странного.

### Перед реализацией изучить

- horse/cart controller;
- физическую связь телеги и лошади;
- animation-driven locomotion;
- nav/path constraints;
- способы не допустить физического хаоса телеги;
- как ограничить транспорт подходящими дорогами.

Приоритет — стабильность и атмосфера, а не реалистичный симулятор лошади.

---

# 10. Татарское радио

В Ниве и, возможно, других транспортных средствах должно работать радио.

Нужна полноценная локальная радиостанция.

Контент:

- татарская музыка;
- татарская речь;
- русский язык;
- прогноз погоды;
- районные новости;
- объявления;
- поздравления;
- передача саламов;
- реклама местных услуг;
- упоминания соседних авылов.

Радио может иногда давать сюжетные подсказки.

### Перед реализацией изучить

- playlist system;
- radio station state;
- сохранение позиции трека при выходе из машины;
- перемешивание музыкальных и речевых сегментов;
- data-driven radio content;
- audio transitions.

Радиосистему желательно сделать расширяемой, чтобы позже просто добавлять новые записи.

---

# 11. Начало игры и автобусная остановка

Игрок начинает игру на автобусной остановке на съезде в деревню.

Это первая точка игры.

Сцена должна создавать ощущение приезда из внешнего мира.

Возможный сценарий:

- автобус только что приехал;
- игрок выходит;
- автобус уезжает;
- шум двигателя исчезает;
- впереди остаётся деревня.

Остановка должна содержать:

- название населённого пункта;
- расписание;
- старые объявления;
- лавку;
- дорогу в авыл.

### Перед реализацией изучить

- существующий spawn system;
- intro logic;
- scene loading;
- возможность сделать простой scripted arrival без тяжёлой cutscene-системы.

---

# 12. Дом бабая

Дом бабая — основная домашняя база игрока.

В доме:

- компьютер;
- фотографии;
- документы;
- бытовые предметы;
- записки;
- шкафы;
- старые вещи;
- баня.

Дом должен ощущаться реально жилым.

Не каждый предмет обязан быть интерактивным.

### Перед реализацией изучить

- реальные татарские сельские дома;
- планировку;
- интерьер;
- бытовые предметы;
- сочетание старых и современных вещей примерно периода 2005–2026.

---

# 13. Баня бабая

Баня должна быть одной из самых напряжённых локаций игры.

Основные элементы:

- печь;
- потрескивание;
- металлические звуки;
- дерево;
- пар;
- слабое освещение;
- высокая влажность;
- конденсат;
- скрип.

Не злоупотреблять скримерами.

Основное чувство — будто в маленьком помещении находится или только что находилось что-то ещё.

### Перед реализацией изучить

- устройство деревенской татарской бани;
- реальные банные печи;
- пар и volumetric effects;
- believable fire audio;
- ambient horror без jumpscares.

---

# 14. Мечеть

Одна из ключевых локаций деревни.

NPC:

**молодой имам**.

Он должен быть современным нормальным человеком:
- пользуется телефоном;
- знает жителей;
- образован;
- может разговаривать просто и естественно.

Мечеть является safe zone.

Внутри:
- основные сверхъестественные атаки не происходят;
- игрок может чувствовать себя безопаснее;
- Шурале не должен просто заходить внутрь вслед за игроком.

Не выводить надпись SAFE ZONE.

### Перед реализацией изучить

- современные сельские мечети Татарстана;
- интерьер;
- организацию пространства;
- роль сельского имама;
- корректное и уважительное отображение исламских элементов;
- техническую реализацию safe zones.

Религиозные предметы не использовать как дешёвые хоррор-реквизиты.

---

# 15. ФАП / медпункт

Небольшой сельский медицинский пункт.

Нужно:

- фельдшер;
- кабинет;
- кушетка;
- шкафы;
- лекарства;
- медицинские плакаты;
- журналы;
- старый компьютер.

Фельдшер может быть одним из NPC, который знает практически всю деревню.

Сложная система лечения не нужна.

### Перед реализацией изучить

- реальные сельские ФАПы Татарстана/России;
- типичную планировку;
- реквизит;
- простой NPC dialogue interaction.

---

# 16. Магазин

Маленький сельский магазин.

Нужно:

- продавщица;
- товары;
- холодильники;
- прилавок;
- доска объявлений;
- разговоры местных жителей.

Игрок может брать необходимые товары.

Отдельную финансовую систему не делать.

Главная механика:

**покупки записываются «на бабая» в долговую тетрадь.**

Пример:

игрок берёт батарейки → продавщица говорит «на бабая запишу» → появляется новая запись.

### Перед реализацией изучить

- маленькие сельские магазины;
- простую item purchase system без денег;
- persistent debt records;
- reusable store interaction.

---

# 17. Закрытая школа

Школа больше не работает.

Причина:

в деревне практически нет детей, а оставшихся возят в другое село.

Большинство помещений закрыто.

Игрок может попасть в несколько частей:

- коридор;
- класс;
- кабинет;
- возможно библиотеку или спортзал.

Внутри:

- фотографии выпускников;
- расписания;
- рисунки;
- стенгазеты;
- стенды;
- документы;
- школьные предметы.

Пасхалки:

игрок может узнавать молодых жителей деревни на старых фотографиях.

### Перед реализацией изучить

- закрытые сельские школы Татарстана;
- школьные интерьеры 1990–2010-х;
- reusable document/photo inspection system.

---

# 18. Сельсовет / ДК

Сельсовет и Дом культуры можно объединить в одно здание.

Внутри:

- административный кабинет;
- архив;
- сцена;
- зал;
- склад;
- старые фотографии;
- планы деревни;
- афиши;
- материалы Сабантуя;
- документы.

Это одна из основных лорных локаций.

### Перед реализацией изучить

- сельские ДК Татарстана;
- реальные сельсоветы;
- архивные стенды;
- сцены и клубы;
- reused document system.

---

# 19. Зират

Нужен настоящий татарский зират.

Не делать из него стандартное хоррор-кладбище.

Нужно:

- старые и новые захоронения;
- татарские имена;
- фамилии;
- даты;
- семейные связи.

Фамилии должны пересекаться с другими источниками:

- школа;
- документы;
- компьютер бабая;
- сельсовет;
- NPC.

### Перед реализацией изучить

- внешний вид татарских кладбищ;
- оформление могил;
- надписи;
- расположение;
- культурные нормы поведения и изображения зирата.

---

# 20. Обычная деревня

Кроме ключевых зданий должны присутствовать:

- жилые дома;
- сараи;
- гаражи;
- огороды;
- теплицы;
- палисадники;
- заборы;
- хозяйственные постройки;
- частные бани;
- машины;
- деревья;
- линии электропередачи;
- сельские дороги.

Не делать интерьер каждого дома.

Главное — правдоподобная структура улиц.

### Перед реализацией изучить

- layout татарских деревень;
- типы домов;
- земельные участки;
- огороды;
- палисадники;
- хозяйственные зоны;
- реальные фотографии современных авылов Татарстана.

---

# 21. Лес

Лес должен ощущаться отдельным пространством.

Главный транспорт — телега.

Сначала лес обычный.

Постепенно появляются:

- странная тишина;
- необычные звуки;
- повторяющиеся ориентиры;
- потеря ощущения расстояния;
- нервозность лошади;
- силуэты;
- следы;
- странное поведение окружения.

### Перед реализацией изучить

- леса Татарстана;
- растительность;
- лесные дороги;
- believable environmental horror;
- procedural или semi-procedural повторение ориентиров;
- audio-driven horror.

---

# 22. Шурале

Шурале нельзя превращать в обычного FPS-монстра.

Он не должен постоянно:

- появляться перед игроком;
- преследовать;
- нападать;
- исчезать по scripted scare.

Присутствие лучше показывать постепенно:

- звук;
- голос;
- движение веток;
- силуэт;
- след;
- неправильное направление звука;

# 23. Общая структура имплементации

Перед тем как начинать разработку, модель должна сравнить всё это с существующим кодом и по каждому разделу определить:

- что уже реализовано;
- что реализовано частично;
- что нужно изменить;
- что нужно удалить;
- что нужно создать с нуля.

Особенно не создавать дубликаты систем.

Сначала изучить существующие:

- Player Controller;
- interaction system;
- notebook;
- save system;
- UI;
- audio;
- vehicle logic;
- forest logic;
- Shurale AI.

1. управление игроком;

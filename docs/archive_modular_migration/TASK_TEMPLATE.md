# MM-XX — Короткое название результата

## Цель

Описать один проверяемый результат, а не общий процесс.

## Основание и границы

- Родительский пакет: `docs/modular_migration/00_ORCHESTRATOR_README.md`.
- Прочитать до начала: перечислить конкретные контракты и предыдущие handoff.
- Входит в задачу: перечислить разрешённые изменения.
- Не входит: перечислить соседние владельцы, совместимость и отложенные возможности.
- TDD Route: `Mode: off`; `Decision: skipped`; тесты добавляются после минимальной реализации как регрессия. Строгий TDD разрешён только отдельным решением пользователя или проекта.

## Владение файлами

Указать точные директории и файлы, которыми владеет исполнитель. Если нужен файл из `forbidden_scope`, исполнитель останавливается и передаёт запрос оркестратору.

## Шаги

1. Проверить входные контракты и чистоту своей рабочей области.
2. Внести минимальные изменения только в `owner_scope`.
3. Добавить сфокусированную проверку результата.
4. Запустить команды из frontmatter и сохранить краткие доказательства.
5. Заполнить handoff ниже без commit, push, merge или изменения соседних пакетов.

## Критерии приёмки

- Результат задачи можно проверить без знания скрытого контекста исполнителя.
- Нет второго владельца, временного fallback или сюжетного ID в общем коде.
- Все локальные проверки проходят; известные внешние блокеры перечислены явно.

## Формат handoff

```text
Task: MM-XX
Status: complete | partial | blocked
Worktree / branch:
Changed paths:
Behavior / contracts delivered:
Verification commands:
Verification results:
Retired owners / remaining callers:
Risks or drift:
Required next task:
```

Не помечать задачу `complete`, если обязательная проверка не запущена или старый владелец остался активен вопреки критериям пакета.
